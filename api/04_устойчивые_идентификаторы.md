# Подключение, устойчивое к переименованию

Ключ привязан к `projectId`, а операции плана — к `disciplineId`, `sectionId` и ID версий. Названия служат для показа человеку. Они могут меняться и совпадать у разных объектов. Сохраняйте ID выбранных объектов в настройках интеграции.

## Первое подключение

1. Выпустите ключ в профиле. Заполните **«Название программы»** и выберите проект. Пустое название оставляет кнопку «Создать ключ» недоступной. Выберите режим «Полный — по роли», если программе нужна запись.
2. Вызовите `GET /api/platform/network-federation/me`. Список `projects` содержит `projectId`, актуальное `name` и роль. Дайте пользователю выбрать проект и сохраните его `projectId`.
3. Прочитайте `GET /api/platform/projects/{projectId}/network-federation`. В `document.disciplines` сохраните `id` нужного раздела; в `document.sections` — `id` файла и его `disciplineId`.
4. Следующие запросы отправляйте с сохранёнными ID. При повторном чтении обновляйте отображаемые названия, не заменяя ID поиском по прежнему имени.

В Python-примерах:

```sh
python examples/python/plan.py --projects
python examples/python/plan.py --project PROJECT_ID
python examples/python/upload_drawing.py --project PROJECT_ID --section-id SECTION_ID --file plan.dwg --unit mm --wait-ready
python examples/python/download_archive.py --project PROJECT_ID --discipline-id DISCIPLINE_ID --out water.zip
```

`--section-id` выбирает существующий файл и определяет его раздел из ответа плана. Можно дополнительно указать `--discipline-id`: несовпадение раздела приведёт к отказу до записи.

## Переименование, удаление и совпадение имён

- Переименование проекта, раздела или файла сохраняет ID и само по себе не требует нового ключа. Уже выданный ключ продолжает действовать в пределах срока и текущих прав владельца.
- Удалённый объект, созданный заново с тем же названием, получает другой ID. Интеграция должна остановиться и предложить повторный выбор; автоматически подменять объект нельзя.
- Для первоначального выбора по имени допускается только одно совпадение. Если их несколько, Python-примеры завершаются с ошибкой и показывают ID кандидатов.
- Если старое имя не найдено, загрузчик больше не создаёт файл автоматически. Чтобы добавить новый файл, явно укажите `--create-section` вместе с разделом и названием. Это изменение поведения примера; для существующей синхронизации замените выбор по имени на `--section-id`.

Пример явного создания файла:

```sh
python examples/python/upload_drawing.py --project PROJECT_ID --discipline-id DISCIPLINE_ID --section "Новый файл" --create-section --file new.dwg --unit mm
```

Это защита клиентского примера от случайной записи в другой объект. Серверный контракт и названия параметров API не менялись.

## Как различить проблемы доступа

- `401 AGENT_TOKEN_INVALID` при проверке `/me`: ключ отсутствует, недействителен, отозван или истёк. Переименование не является причиной для перевыпуска. Проверьте состояние ключа в профиле.
- `403 AGENT_GRANT_DENIED`: проверьте режим ключа («Чтение» не разрешает запись) и доступность маршрута для ключей. Даже полный ключ не открывает служебные маршруты. Другие `403` проверяйте по коду: роль, участие, право записи в раздел.
- `404 PROJECT_NOT_FOUND`: проверьте `projectId`, список проектов ключа в `/me` и текущий доступ владельца. `404` для файла или другого объекта — проверьте ID и актуальный план. Не переключайтесь автоматически на одноимённый объект. Пустой `404` самого `/me` также может означать, что API выключен в этом окружении; см. быстрый старт.

При замене ключа сначала проверьте новый ключ в программе, затем отзывайте старый. После отзыва старый секрет больше не работает и не восстанавливается. В сообщении об ошибке сохраняйте HTTP-статус, код ошибки, адрес без секрета и время запроса; значение ключа не записывайте.
