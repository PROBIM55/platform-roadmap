# Соглашения

## Адрес и заголовок

- Базовый адрес: `https://bimplatforma.ru`. Все маршруты начинаются с `/api/platform/…`.
- Каждый запрос — с заголовком `Authorization: Bearer <ключ>`. Ключ в адресе и в cookie не принимается.
- Тела запросов и ответов — JSON в кодировке UTF-8 (`Content-Type: application/json`), кроме загрузки файлов (`application/octet-stream`), шрифтов (`multipart/form-data`) и скачивания.
- Имена полей — в `camelCase`. Время — в UTC, в формате ISO 8601. Размеры — в байтах, координаты размещений — в миллиметрах.
- Программа должна игнорировать незнакомые поля в ответах: сервер может добавлять новые.

## Формат ошибок

Ошибка — это код статуса и JSON-тело:

```json
{ "ok": false, "error": "NETWORK_DISCIPLINE_WRITE_DENIED" }
```

Ошибки модуля приходят именно в таком виде. Ошибки уровня платформы (доступ к проекту, лимиты) могут добавлять поля `message` и `details`. Запрос с недействительным, отозванным или просроченным Bearer-ключом получает 401 и JSON `{ "ok": false, "error": "AGENT_TOKEN_INVALID", "message": "..." }`. При включённом API маршрут проверки ключа `GET /api/platform/network-federation/me` возвращает такой JSON и при отсутствии заголовка. Запросы к маршрутам проекта без Bearer-заголовка могут вернуть 401 с пустым телом. У 429 время ожидания лежит в заголовке `Retry-After`, а также в `details.retry_after_seconds` или в корне тела (`retry_after_seconds`).

Программа должна ветвиться по `error` (стабильный код), а не по `message`. У части отказов тела нет: 404 при скачивании файла, которого нет. Успех — статус 2xx; у ответов с данными обычно `"ok": true`.

Слой ключа добавляет к кодам модуля свои:

| Статус | Код | Когда |
|---|---|---|
| 401 | `AGENT_TOKEN_INVALID` | Bearer-ключ недействителен, отозван или просрочен. На маршруте проверки ключа — также при отсутствии ключа. Тело — JSON `{ok:false, error, message}`. |
| 403 | `AGENT_GRANT_DENIED` | Запись ключом «Чтение» или закрытый для ключа маршрут. |
| 404 | `PROJECT_NOT_FOUND` | Проект вне списка ключа или чужой компании — без различий между этими случаями. |
| 403 | `API_KEY_EMPLOYEES_ONLY` | Ключ выпускается только сотрудникам компании. |
| 400 | `API_KEY_WITH_SESSION` | В запросе одновременно ключ и cookie сессии. |
| 409 | `API_KEY_LIMIT` | При выпуске ключа: у человека уже 10 действующих ключей — отзовите ненужный. |
| 400 | `API_KEY_PROJECTS_ONE_COMPANY` | При выпуске ключа: проекты из разных компаний — один ключ на одну компанию. |
| 429 | `RATE_LIMIT_AGENT_READ` / `RATE_LIMIT_AGENT_WRITE` | Превышен лимит (см. ниже); есть `Retry-After`. |

Остальные коды — те же, что видит интерфейс (`NETWORK_…`, `CAD_UPLOAD_…`, `COMPARISON_…` и другие). У каждого маршрута их список — в [справочнике](reference.md). Частые отказы модуля: 403 `PROJECT_ACCESS_DENIED` (вы не участник проекта), 403 `PROJECT_MODULE_ACCESS_DENIED` (в проекте нет сводного плана), 403 по роли (`NETWORK_ADMIN_REQUIRED`, `NETWORK_COORDINATOR_REQUIRED`, `NETWORK_DISCIPLINE_WRITE_DENIED`, `NETWORK_SOURCE_ACCESS_DENIED`).

## Версия документа (`expectedVersion`)

Сводный план — один документ с номером версии. Маршруты, которые меняют его состав или решения (принять, вернуть, снимок, размещение, порядок отрисовки, настройки раздела, уточнение единиц), требуют в теле поле `expectedVersion` — номер версии документа, на основе которого вы принимаете решение. Его берут из `document.version` ответа `GET …/network-federation`.

- Поля нет — **428** `NETWORK_DOCUMENT_VERSION_REQUIRED`.
- Документ с тех пор изменился — **409** `NETWORK_FEDERATION_DOCUMENT_CONFLICT`. Перечитайте план, убедитесь, что решение всё ещё верно, и повторите запрос с новой версией. Не повторяйте тот же запрос вслепую в цикле.

Это защита от ситуации, когда вы приняли версию, которую человек уже вернул минутой раньше. Не все маршруты требуют `expectedVersion`: загрузка и регистрация версии, участники и права его не используют. У обсуждений и видов своя защита — поле `rowVersion` каждого обсуждения, сообщения, вида или конфигурации. Его берут из последнего ответа; без него 428 (`NETWORK_DISCUSSION_ROW_VERSION_REQUIRED`, `NETWORK_VIEW_ROW_VERSION_REQUIRED`), при расхождении 409 — перечитайте и повторите. В запросах `DELETE` `rowVersion` передают параметром адреса.

## Лимиты

- **Чтение — 600 запросов в минуту на ключ, запись — 120 в минуту.** Чтения — `GET`, `HEAD` и три чтения показа методом `POST` (диапазоны тайлов отрисовки, разбор шрифтов одной версии и пакетом). Записью считаются остальные запросы; каждый кусок загрузки — тоже запись.
- Действующих ключей у человека — не больше 10, поэтому лимиты нельзя умножить, выпустив много ключей.
- Превышение: **429** с кодом `RATE_LIMIT_AGENT_READ` или `RATE_LIMIT_AGENT_WRITE`. Заголовок `Retry-After` и поле `details.retry_after_seconds` — через сколько секунд повторить. Подождите столько и повторите; не «долбите» сервер.
- Значения лимитов могут быть изменены для ключа без выпуска нового ключа; закладывайтесь на ответ 429, а не на число.
- Другие лимиты: файл чертежа — до размера из `GET …/uploads/limits` (по умолчанию 64 МиБ), кусок — до 8 МиБ, модель IFC — до 512 МиБ, вложение обсуждения — до 25 МиБ.

Ответы `429` с другими кодами (`CAD_IMPORT_QUEUE_FULL`, `CAD_IMPORT_STORAGE_QUOTA_EXCEEDED`, `CAD_FONT_UPLOAD_BUSY`) — ограничения сервера, а не ключа: повторить позже.

## Повторы запросов

Сеть обрывается. Знайте, что безопасно повторять.

**Безопасно повторять:**

- все запросы `GET`;
- `PUT …/uploads/{sessionId}/content` с тем же `Content-Range`: сервер сверяет уже принятые байты и ничего не записывает дважды (при расхождении байт — 409 `CAD_UPLOAD_CHUNK_CONFLICT`). После обрыва прочитайте сессию (`GET …/uploads/{sessionId}`) и продолжайте с `receivedBytes`;
- `POST …/uploads/{sessionId}/complete`: для уже завершённой сессии возвращается тот же импорт;
- `POST …/sections/{sectionId}/cad-versions` с тем же импортом: если в этом файле уже есть версия с той же контрольной суммой SHA-256 и теми же единицами, возвращается она — в любом статусе, в том числе «возвращена» (то же верно для версии модели IFC). Поэтому загрузка неизменённого файла второй раз не создаёт новую версию и не отправляет ничего на проверку;
- `PUT` и `DELETE` без версии записи: участники и права, переименование раздела, назначения — повтор того же значения ничего не меняет (для `DELETE` повторный вызов может вернуть 404);
- создание снимка с одним `idempotencyKey` и создание обсуждения с одним `clientRequestId`.

**Если ответ записи с версией (`expectedVersion` или `rowVersion`) потерян, перечитайте состояние и сравните его с намерением запроса.** Повтор с прежней версией после сохранённого изменения получит 409. Некоторые операции сохраняют текущую версию, если данные уже совпадают. Например, повтор порядка разделов или чертежей с актуальным `expectedVersion` возвращает 200 без изменения версии. Успешный ответ сам по себе не гарантирует увеличения версии, используйте номер из ответа или перечитайте документ.

**Не повторяйте вслепую** (повтор создаст второй объект): ответ в обсуждении (`POST …/discussions/{id}/messages`), приглашения, ссылки просмотра, создание метки или вида, открытие новой сессии загрузки (лучше продолжить прежнюю). Если ответ потерян, сначала прочитайте состояние и проверьте, что запись уже есть.

Для записей с `expectedVersion` повтор после 409 делайте только после перечитывания плана.

## Прекращайте обход после первого отказа

Сервер следит за запросами, похожими на сбор данных по перебору. Если ваша программа получила отказ по проекту (403 или 404 на проекте, разделе, файле или версии), она **должна прекратить работу по этому проекту** и сообщить человеку, а не перебирать соседние идентификаторы, другие проекты или «угадывать» адреса. Иначе сработает защита, и **ключ будет отозван**.

Правила честной программы:

- берите идентификаторы только из ответов сервера (план, списки), не придумывайте и не перебирайте их;
- не обходите проекты, которых нет в ответе `GET /api/platform/network-federation/me`;
- на 401 и 403 с кодами ключа (`AGENT_TOKEN_INVALID`, `AGENT_GRANT_DENIED`) остановитесь целиком;
- на 429 ждите `Retry-After`;
- не запускайте несколько копий программы с одним ключом без необходимости.

## Загрузка файлов кратко

Чертёж DWG или DXF грузится сессией: открыть сессию → куски до 8 МиБ с заголовком `Content-Range` → `complete` → дождаться окончания импорта → зарегистрировать версию. Модель IFC — одним запросом без сессии. Пошаговые запросы — в [сценариях](03_сценарии.md).

## Совместимость и журнал изменений

- Маршруты, параметры и ответы описаны в [справочнике](reference.md) и [OpenAPI](openapi.json).
- Изменение маршрута или формы ответа сводного плана сопровождается правкой каталога и записью в [журнале изменений](CHANGELOG.md).
- **Совместимыми** считаются: новые маршруты, новые необязательные поля в запросах, новые поля в ответах, новые коды ошибок у существующих сбоев. **Несовместимые** изменения (удаление или переименование маршрута или поля, новое обязательное поле, смена смысла) помечаются в журнале явно словом «НЕСОВМЕСТИМО».
- Служебные маршруты показа (в справочнике помечены) могут меняться без такой пометки. Для интеграций используйте остальные.
- Номер версии API указан в `openapi.json` (`info.version`).
