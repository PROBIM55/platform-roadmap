# API сводного плана сетей

Программный доступ к модулю «Сводный план сетей» платформы: то же, что человек делает в интерфейсе, но из программы — прочитать план, скачать чертежи и архив, загрузить новую версию, пройти проверку версий, вести участников, обсуждения и виды.

Базовый адрес рабочего сервера: `https://bimplatforma.ru`.

> Программный доступ включён на рабочем сайте. Сотрудник с доступом к проекту СКП может выпустить личный ключ в профиле, в разделе «Программный доступ». Для выпуска нужен вход не старше 15 минут.

## Главное

- **API — это те же маршруты, что у интерфейса.** Отдельной «программной» поверхности нет: программа вызывает маршруты модуля `/api/platform/projects/{projectId}/network-federation/…` и связанные с ними. Новая кнопка в интерфейсе — это новый маршрут, который сразу доступен программе и попадает в [справочник](reference.md).
- **Ключ — личный ключ сотрудника компании.** Его выпускает сам сотрудник в профиле. Ключ действует текущими правами своего владельца в сводном плане и только в тех проектах своей компании, которые выбраны при выпуске. Координатор по ключу может то же, что координатор в интерфейсе; исполнитель («Загрузка») — только своё.
- **Для кого.** Для сотрудников компании, которые пишут свои программы и скрипты: синхронизацию чертежей, выгрузки, отчёты. Гости и подрядчики из других организаций ключей не получают и работают через интерфейс.
- Проверки ролей, разделов, ворот проверки версий, защита от параллельных правок и коды ошибок — те же, что в интерфейсе.

## Быстрый старт за 5 минут

Начните с окружения, в котором включён программный доступ к сводному плану. Если точный адрес запроса из шага 3 возвращает пустой `404`, проверьте базовый адрес и доступность API в этом окружении. Администратор окружения включает API параметром `ServerOptions.EnableNetworkPlanApi` и перезапускает сервер. При выключенном параметре маршрут проверки ключа и управление ключами возвращают пустой `404`. При включённом API запрос к маршруту проверки без ключа или с недействительным ключом возвращает `401` с кодом `AGENT_TOKEN_INVALID`. Для локального стенда замените базовый адрес в командах `curl` или задайте `PLATFORM_BASE_URL` для примеров на Python. Используйте ключ, выпущенный в том же окружении.

1. **Создайте ключ.** В профиле откройте «Программный доступ» → «Создать ключ». Укажите название программы, проекты, режим («Чтение» для начала) и срок. Секрет показывается один раз — скопируйте его в надёжное место. Подробности — в [01_ключ_доступа.md](01_ключ_доступа.md).
2. **Передайте ключ программе через переменную окружения**, а не в тексте скрипта:

   ```
   PowerShell:            $env:PLATFORM_API_KEY = "bpk_..."
   Командная строка:      set PLATFORM_API_KEY=bpk_...
   Linux и macOS:         export PLATFORM_API_KEY=bpk_...
   ```

3. **Проверьте ключ первым запросом** — он покажет, чей это ключ, режим, срок и проекты:

   ```
   Linux и macOS:   curl -H "Authorization: Bearer $PLATFORM_API_KEY" https://bimplatforma.ru/api/platform/network-federation/me
   PowerShell:      curl.exe -H "Authorization: Bearer $env:PLATFORM_API_KEY" https://bimplatforma.ru/api/platform/network-federation/me
   Командная строка: curl.exe -H "Authorization: Bearer %PLATFORM_API_KEY%" https://bimplatforma.ru/api/platform/network-federation/me
   ```

4. **Прочитайте сводный план проекта.** Идентификатор проекта берут из ответа предыдущего запроса:

   ```
   curl -H "Authorization: Bearer $PLATFORM_API_KEY" https://bimplatforma.ru/api/platform/projects/{projectId}/network-federation
   ```

   (в PowerShell и командной строке Windows — `curl.exe` и `$env:PLATFORM_API_KEY` или `%PLATFORM_API_KEY%`, как выше)

   В ответе: разделы (`document.disciplines`), файлы разделов (`document.sections`) с версиями чертежей, ваши права (`permissions`), участники и номер версии документа `document.version`.
5. **Попробуйте готовый пример** на Python — он не требует сторонних библиотек:

   ```
   python examples/python/plan.py --project {projectId}
   ```

Дальше — [сценарии](03_сценарии.md): скачать архив, загрузить версию чертежа, проверить версии.

## Термины

- **Раздел** — раздел сводного плана, например «Водоснабжение» (в адресах и ответах `discipline`).
- **Файл** — карточка чертежа внутри раздела (в адресах `sections`). В файле лежат версии.
- **Версия** — загруженный вариант чертежа (`cad-versions`) или модели IFC. Статусы: «на проверке» (`submitted`), «актуальная» (`accepted`), «возвращена» (`returned`).
- **Роли в проекте:** «Администратор», «Координатор», «Загрузка» (исполнитель назначенных разделов), «Просмотр».
- **Режимы ключа:** «Чтение» — запросы GET и HEAD и три чтения показа методом POST (тайлы, шрифты); «Полный — по роли» — запись в пределах роли владельца.

## Примеры в этой папке

Примеры читают ключ из переменной `PLATFORM_API_KEY`, адрес — из `PLATFORM_BASE_URL` (по умолчанию `https://bimplatforma.ru`). Они не печатают ключ и останавливаются после первого отказа по проекту. Это образцы для начала, а не готовые продукты: прочитайте код, прежде чем запускать запись.
